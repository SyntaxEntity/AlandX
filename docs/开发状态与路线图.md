## 一、一句话现状

**功能面基本铺满了，但几乎没有一条路径在真实接口上跑通过。** 站点 `api.nmb.best` 自 10-21 起整站 502，
所有网络链路至今只有静态检查与编译验证，没有真机数据验证。

之所以"看起来只有主页"，是因为「版面」「订阅」两栏的内容完全依赖接口——
接口挂了就渲染成空列表，视觉上和"没做"没有区别。实际上这两页各有 273 / 488 行实现。

## 三、明确没做

- **推送 / 订阅轮询**：接口没有推送能力，只能前台轮询 `/feed?uuid=`，本轮明确不做
- **请求重试与退避**：一次失败即报错，没有指数退避
- **跨串引用的跳转**：点 `>>No.` 现在只在本串内定位；若引用的是别的串，会提示"不在这几页里"而不是跳过去
- **HTML 渲染的标签覆盖**：`RichContent` 只认 `br/a/img/ul/li/b/i/u/del`，其余标签会被当纯文本

> 深色模式、图片缓存、楼层定位、单测、lint 已在本轮补齐，见开头表格。

## 四、和 FlClash 的对应关系

底栏是照 FlClash 的 `NavigationDock` 交互写的，但**没有复制它的源码**，原因有两个：

1. **许可证**。FlClash 以 **GPL-3.0** 分发。把它的代码搬进本项目，本项目就必须整体改为 GPL-3.0
   并附带源码提供义务。当前项目是"仅供学习交流"的模糊状态，不应被动继承 GPL。
2. 取源码的过程也不顺：`github.com` 被墙，`jsdelivr` 对部分文件 404/503，`codeload` 源码包
   下载到 7.4 MB 时被限速截断。最终只读到 `lib/pages/home.dart` 这一层的调用契约。

所以实现方式是**按观察到的行为契约重写**：

| 维度 | FlClash | 本项目 |
|---|---|---|
| 悬浮与否 | 悬浮，`NavigationDock.insetOf` 给内容让位 | 一致 |
| 选中项形态 | 横向展开露出文字 | 一致 |
| 切换手势 | 底栏上横向滑动 | 一致 |
| 位置模型 | `PageController` + `PageView`，`NeverScrollableScrollPhysics` | 单个 `_pos` 浮点位置 + `AnimationController` 吸附 |
| 标签显隐 | 未确认 | `ClipRect + Align(widthFactor)` 横向拉出 |
| 宽度动画 | 未确认 | 相邻两项权重和恒为 1，总宽不变 |
| 触觉反馈 | 未确认 | 跨格 `HapticFeedback.selectionClick()` |

差异点集中在上表后三行——那是原实现的内部做法，无法从外部观察，属于自行设计。

## 五、开发计划

### P0 · 让"能否跑通"有答案（仍然阻塞）

1. 站点恢复前无法验证真实读链路；真机体验由项目所有者自行完成
2. **写接口路径大小写仍未改**：`api.dart` 里是 `/home/forum/doPostThread.html`，
   X岛网页端为 `/Home/Forum/doPostThread.html`。Linux 下 PATH_INFO 大小写敏感，
   很可能是发串失败的直接原因。**故意留到站点恢复后再一起验证**，避免盲改引入新变量。
   已列为恢复后的第一件事。

### P1 · 去网页感 —— ✅ 已完成

`lib/theme.dart` 引入 `AppPalette`，把 `kInk/kInk2/kInk3/kOutline` 从常量改成
跟随 `ColorScheme` 的 getter，127 处调用点无需改写即可支持明暗两套；
`SurfaceCard` 去掉描边改用 `surfaceContainerLow`；`themeMode: system` 生效。

### P2 · 补功能 —— ✅ 除订阅轮询外全部完成

楼层定位、图片磁盘缓存、发串草稿、未登录提示 + 饼干教程均已落地；
订阅更新轮询按需求明确不做。

### P3 · 工程质量 —— ✅ 已完成

`flutter_lints` 已启用，CI 用 `--no-fatal-infos` 保证 error/warning 仍阻塞；
`parseJumpHtml` / `parseSearchHtml` 对外开放并补了 13 条单测；
签名脚本与 CI 注入逻辑已就绪，**待项目所有者生成密钥库并配置 4 个 secrets**。
